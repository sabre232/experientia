Style de code :
- Suivre le style existant du repo (indentation, nomenclature, ordre des imports) ; le nouveau code reste cohérent avec le code voisin ; NEVER re-formater au passage des fichiers sans rapport.
- Les commentaires ne notent que les contraintes que le code lui-même ne peut pas exprimer ; pas de remplissage du type « ici on appelle X ».
