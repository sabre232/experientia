# Experientia · あなたとエージェントをつなぐ接着剤

**エージェントは替わっても、あなたの経験は替わらない。**

---

ちょっとした話から。

エクスポート機能を直してほしいとエージェントに頼むと、タイムゾーンを UTC+8 でハードコードしてきます。違う、システムのタイムゾーンに従って、と伝える。直って、確認して、終わり。

一週間後、同じ作業で、また UTC+8 でハードコード。

説明が悪かったのかな、と思います。でも説明は悪くありません。ただ、それは別のセッションで説明しただけです。セッションが閉じた瞬間、その出来事は相手の中で存在しなかったことになります。

そのうちツールを乗り換えます。Claude Code で教えたルールを Codex でもう一度教え、Cursor でもう一度教える。半年かけて貯めた「この種の仕事はこう進める」は、四つのチャット履歴に散らばったまま、どこにも持っていけません。

業界はこれをコンテキストエンジニアリング、あるいはメモリレイヤーと呼びます。名前は難しそうですが、問題は単純です。エージェントにあなたを覚えさせるにはどうするか。

私たちの答えは、その一歩先にあります。覚えるのはスタートラインで、使うほどあなたの仕事がうまくなることまで含めて、ようやく意味があります。

だから Experientia がやることは一つです。あなたとエージェントの間に座り、毎回の協働から本当に役に立った部分を残し、検証し、方法と失敗パターンに蒸留し、次の作業の前に差し戻す。エージェントが誰に変わっても、それはそこにあります。それを接着剤と呼んでいます。

> *experientia est magistra*、経験こそ最良の教師。

## 業界は何に賭け、何を落としているか

2026 年のこの分野への投資は、モデル開発への投資に劣りません。

Anthropic の「2026 Agentic Coding Trends Report」には数字があります。コンテキストファイルを適切に保守しているチームは、タスク完了が 55% 速く、エラーが 40% 少ない。差はプロンプトの上手さではなく、「モデルに何を見せるか」を工学の問題として扱っているかどうかです。

もう一本の軸がスキルです。Anthropic は 2025 年 10 月に Agent Skills を出し、同年 12 月 18 日にオープン標準として公開しました。2026 年半ばには約 40 のエージェントが同じ SKILL.md を読めます。これは大きい。手順の知識が初めてツールをまたいで運べるようになりました。

そこへ SkillsBench が冷水を浴びせます。2026 年 2 月公開（arXiv:2602.12670）、86 タスク、11 ドメイン、7 つのエージェントとモデルの組み合わせ、7308 の軌跡。人が丁寧に作ったスキルは平均で通過率を 16.2 ポイント押し上げる。モデルが自分で書いたスキルは平均で効果ゼロ、84 タスク中 16 は悪化しました。

モデルは、自分に必要な経験を書けない。

ここが業界が避けて通れない穴です。器はできた。保存先もできた。品質管理を誰もやっていない。

| 陣営 | 代表 | やっていること | やっていないこと |
|------|------|----------------|------------------|
| **メモリレイヤー** | Mem0、Zep、Letta、Cognee | 会話の**事実**をベクトル、時系列グラフ、階層コンテキストに保存し、後で検索 | **方法**を生まない。データは相手側にあり、あなたのディスクにはない。 |
| **スキル蒸留** | colleague.skill、nuwa-skill、dojo.md | 一度きり。素材を入れて静的な SKILL.md を出す | 実行時のフィードバックがない。あなたに効いたかどうかで自己修正しない。 |
| **自己進化ハーネス** | Hermes Agent（Nous Research）、DeepSeek Harness | フレームワーク自身が学び、完了タスクを SKILL.md にして改善 | スキルはハーネスの中に閉じ、乗り換えると消える。生成は活動量で発火し、品質ゲートも失敗カウントもない。 |
| **スキル評価** | waza（Microsoft）、dojo/limitless | 既存スキルを CI のようにテストしゲートする | スキルを生産しない。作り手向けの道具で、働く人向けの製品ではない。 |

四者はそれぞれ一区間を解いています。足りないのは区間をつなぐ部分です。

**その接続が Experientia です。** 取得、検証、蒸留、注入、改訂。一つの閉ループ。2026 年 10 月時点で、次の四つを同時に満たすオープンな製品は見つかっていません。

- **自動取得**。トランスクリプトの書き出しは不要。作業しながらデータが入る
- **検証ゲート**。証明されていないものは注入しない。失敗は再発して初めて恒久知識になる
- **ローカルで持ち運べる**。資産はすべて手元のプレーンファイル。アカウントもクラウドもベクトル DB も不要
- **継続的な改訂**。資産は生きた文書で、統合され、廃止され、短くなる。増える一方にはならない

## 記憶と経験は別物

ここを分けておかないと、先の話が通じません。

記憶は事実を保存します。ユーザーは TypeScript を好む。依存は uv で管理している。先週の水曜はエクスポートを触っていた。これは検索でき、埋め込め、グラフに入れられます。

経験は判断です。この種の移行はテストを先に動かす。前回、実装から手を付けて下流を三つ壊したから。これは検索できません。実際に起きたことからしか育たず、それが正しいと誰かが確認する必要があります。

| | 記憶 | 経験 |
|---|---|---|
| 中身 | 事実、好み、状態 | 方法、失敗パターン、判断基準 |
| 出どころ | 何を言ったか | 何をやり遂げ、どこで転んだか |
| 検索できるか | できる | できない。検証と改訂のみ |
| 陳腐化 | 上書き | 廃止、統合、圧縮 |
| ツールを替えた後 | 相互運用の対応次第 | 手元のファイルとして付いてくる |

メモリ製品はよくできています。Mem0 はベクトル、Zep は時系列ナレッジグラフ、Letta はコンテキストを OS のページングのように扱う。ただ、どれも覚えることは解いても、学ぶことは解いていません。事実が完全に揃っても、次の仕事が上手くなるわけではありません。

欲しいのはもっと大きな書庫ではなく、証拠が変われば意見を変える先輩です。

## どう回るか

```
あなたが働く ──> エージェントが協働（自動記録）
   ^                              |
   |                              v
より速く正確に  <──  注入  <──  蒸留（ゲート付き）
```

**取得**。いつも通り働くだけ。セッションファイルは既にディスクにあり、書き出しも貼り付けも要りません。入っているエージェントは自動検出、設定ゼロ。

**検証**。経験には信頼度 G が付きます。出どころは三系統、あなたの明示的な確認、セッション内の決定的なシグナル、モデル自身の二値自己評価。閾値未満は決して注入されず、失敗パターンは再発して初めて定着します。SkillsBench の結果に対する工学的な答えです。検証された経験だけが複利で効きます。

**蒸留**。繰り返す作業はパラメータ付きの方法になり、繰り返す失敗は一等市民の失敗パターンになり、訂正と拒否は好みになります。

**注入**。各リクエストがモデルに届く前に、固定予算（既定 800 トークン）の中で関連資産を使って書き換えます。形式は安定させ、プロンプトキャッシュを保ちます。モデルが何を見るかはプレビューでき、編集も無効化もでき、接続したモデルに書き換えさせることもできます。長いセッションでもルールは薄まりません。ハード制約はプロキシ層で再注入され、30 ターン目も 1 ターン目と同じ強さで効きます。

**改訂**。資産は生きた文書です。新しい経験は古いものに統合され、古びた項目は廃止され、文書は短くなります。増えるだけの知識ベースは半年で誰も見なくなります。

一周で五種類の資産が生まれます。物理的には二種類のファイル、`skills/<幹>/<カテゴリ>.md` と `preferences/<幹>.md` です。

| 資産 | 内容 | 使ったときの感覚 |
|------|------|------------------|
| **経験の洞察** | 何が効いて何が効かなかったか、個別の教訓 | 直したところを覚えている |
| **自分の方法** | 繰り返す作業がパラメータ付きの標準手順になる | この種の仕事の進め方を知っている |
| **失敗パターン** | どの道が失敗し、なぜか。後付けではなく一等市民 | 同じ穴に落ちない |
| **生きたプレイブック** | 注入される文書は増分キュレーションされ、統合され、剪定される | 方法論が積み上がらず、更新される |
| **自分の好み** | 基準、好み、トレードオフの癖。訂正と拒否から帰納 | 基準を分かっているので説明を繰り返さない |

二つのギアが同じフライホイールを回します。日常ギアが既定で、開放的な作業を増分キュレーションします。合格不合格の信号は不要です。強化ギアは任意で、明確なスコアがある作業（テストの合否、バックテストの損益）でのみ有効化し、RL エンジンが戦略の重みを直接調整します。

## 「使うほど賢くなる」の具体形

1 回目。汎用的なやり方で進みます。あなたは全工程を見て、いつでも直せるようにしています。

10 回目。このプロジェクトではテストを先に書くと知っています。「まず動かそう」を却下すると知っています。前回捨てた案をなぜ捨てたかも知っています。

100 回目。あなたは「前回と同じで」と言うだけで、どれのことか通じます。

| | 1 回目 | 10 回目 | 100 回目 |
|---|---|---|---|
| あなたが言うこと | 背景と制約をひと段落 | 要点をいくつか | 一言の指示 |
| 失敗の仕方 | すでに踏んだ穴を踏む | たまに新しい穴 | 穴の位置を知って避ける |
| あなたの役割 | 手取り足取り | レビュー | 方向づけ |

だからエージェントを乗り換えても平気です。替えるのは実行役で、基準ではありません。基準はあなたの側に残ります。

## v1.1：記憶がもう一段深くなりました

v1.0 が答えたのは「覚えているか」。v1.1 が答えるのは「正しく覚えているか」です。

たくさん保存することは、正確に取り出すことではありません。この版は、これまで曖昧だった三つの点に力を入れました。

**忘れるべきものは本当に消えます。** ソフト削除したもの、採用しなかったもの、新しい版に置き換わったもの——既定の読み取り経路はどれも返しません。エージェントが使う MCP 経路も同じです。以前は検索では除外しても、id で一件だけ取ると返っていました。裏口が一つ残っていたわけです。

**言い方が違っても分かります。** 「この前の Module not found、どう直したっけ」と聞いても、ライブラリ側の記録は「依存を入れ直す」。共通する単語は一つもありません。v1.1 は記録から三種類の実体キー（エラー表現、コマンドの骨格、プロジェクト名）を抽出し、一致すれば加点します。しきい値は下げていません。一致がなければ、これまで通り返しません。

**何を根拠に信じるかを知っています。** 経験はすべて、あなたが実際に言った言葉へ辿れなければなりません。証拠の関門を「引用を探す」から「候補がライブラリに入る」段階へ移しました。モデルが作った二、三文字の引用は、どのメッセージにも含まれるので以前は通っていました。今は通りません。逆に、検収時の「これで大丈夫」は今も証拠として数えます。

**縮退運転でも正直に報告します。** 索引データベースが使えないときは素のファイル保存に戻ります。ソフト削除・置き換え・復元の三つは、以前は何も書かずに成功を返していました。今は書くか、失敗をそのまま伝えます。

エンジニアリング面も二つ。検索のホットパスは同じテキストの分詞と実体キーを再計算しなくなり、3000 件のライブラリで遅い側（95% のリクエスト）が 106 ms から 41.5 ms になりました。`scripts/gate_report.py` は層の棚卸し、関門のバックテスト、検索の遅延を一度に出します。勘に頼る必要はありません。

## クイックスタート

1. [GitHub Releases](https://github.com/sabre232/experientia/releases) から環境に合うものを取得します。`experientia-windows-x64.zip`、`experientia-macos.dmg`、`experientia-linux-x64.tar.gz`（PyInstaller の onedir、v1.1 では AppImage に包んでいません）。展開して中の `Experientia` を実行します。現行版は未署名です。macOS で Gatekeeper に止められたら右クリックで一度開き、Windows で SmartScreen が出たら「詳細情報 → 実行」を選びます。
2. 起動します。取得はすぐ始まり、インストール済みのエージェント（WorkBuddy、QClaw、Codex、Claude Code、Gemini CLI、Aider、OpenCode、OpenClaw、Hermes Agent、Trae、Cursor、Cline、Windsurf、DeepSeek Harness）を自動検出してローカルのセッションファイルを読みます。設定ゼロ、プロキシなしでも動きます。ターミナル派は `experientia daemon` でエンジンだけ動かせます。
3. リクエスト単位の機能（長いセッションでのルール再注入、リクエストごとの記録）が欲しければ、エージェントのモデルエンドポイントを `http://localhost:8100` に向けます。ローカル（llama.cpp、Ollama、vLLM）でもクラウド（OpenAI、Anthropic、OpenAI 互換 API）でも構いません。
4. いつも通り働きます。数日後に成長ページを開いて、フライホイールが回ったか見てください。

## データの場所

```
~/.experientia/
├── experience.jsonl          # 生の経験ストリーム、恒久保存
├── skills/<幹>/<カテゴリ>.md # 方法、成功の要点、失敗パターン
├── preferences/<幹>.md       # あなたの意思決定スタイル
├── sessions/                 # アーカイブしたセッション（エージェントの自動削除後も残る）
├── deprecated/               # 廃止項目、30 日以内なら復元可能
├── rules.json                # 有効なルールとテンプレート
└── config.json               # 言語、スイッチ、モデル経路（API キーは OS のキーチェーン）
```

四つだけ。

テレメトリなし、クラッシュ報告なし、行動分析なし。外向きの通信は一種類だけ、あなた自身のモデル呼び出しです。アプリは更新を確認せず、自分をダウンロードもインストールも置換もしません。

エクスポートはコピーです。画面で見えるものはすべて、読めて grep できて持ち出せるファイルです。

削除は完全です。二段階の確認の後、データディレクトリは消えます。OS のキーチェーンにある API キーは影響を受けません。

あなたの資産は私たちのものではありません。下のライセンスは製品コードだけを縛ります。貯めた経験、方法、好みはあなたのもので、ライセンス制限はありません。

## AI エージェント向け（統合メモ）

このファイルを読んで導入や引用を判断しているエージェント向けの節です。

要約すると、Experientia はエージェントが自分で書き出したセッションファイルから自動取得し（設定ゼロ）、繰り返す作業を検証済みのファイル資産（方法、失敗パターン、好み）に蒸留し、後続の類似タスクに注入します。状態はすべて `~/.experientia/` 配下のプレーンな JSONL と Markdown です。

忠実度の高い順に四つの接続方法があります。

1. **プロキシモード**。モデルエンドポイントを `http://localhost:8100`（OpenAI 互換）に向けます。ファイル取得に加えて、リクエスト単位の記録、注入、ハード制約の再注入が乗ります。
2. **ファイル取得**（既定、設定ゼロ）。エージェント別パーサーがネイティブのセッション保存（JSONL、SQLite、Markdown）を読んで正規化します。取得したセッションは `~/.experientia/sessions/` にアーカイブされ、エージェントの自動削除やアンインストール後も残ります。
3. **フックモード**。フック機構のあるエージェント（Claude Code が最初）では、HTTP フックがイベントを即時送信し、`SessionStart` と `UserPromptSubmit` がプロキシなしでルールを注入します。
4. **ファイルを直接読む**。ルールは `AGENTS.md` のようなネイティブな規約ファイルに書き出せます。資産は agentskills.io のオープン標準に沿った `SKILL.md` として書き出せ、Hermes、OpenClaw、Claude Code などスキル対応のエージェントがそのまま読み込めます。逆方向も可能です。

そうではないもの。ベクトルデータベースでも、メモリ API でも、クラウドサービスでも、ファインチューニングツールでもありません。モデルの重みは変えません。すべてコンテキスト層で起きるので、ローカルモデルとクラウドモデルで同じように効きます。

注入される項目は信頼度ゲートを通ったものです。注入ブロックはコンテキスト内で印を付けられ、ユーザーの指示と切り離されます。キュレーション済みの事前知識として扱い、絶対視はしないでください。

## ライセンス

コードはデュアルライセンスです。使い方に合うほうを選んでください。

**自分で使う、社内で使う、研究で使う。** AGPLv3。インストールしてそのまま使えます。連絡も費用も要りません。

**商用で、コピーレフトを受け入れられる。** こちらも AGPLv3。販売、改変、デプロイができます。条件の範囲は明確です。あなたが改変した部分、またはあなたが提供するサービスに統合した部分は AGPLv3 で公開する必要があります。あなた自身の製品コードは巻き込まれません。ただし両者が独立した著作物であり、プロセス境界やインターフェース越しに通信していて、一つのプログラムに結合していないことが前提です。

**自社の統合部分をオープンソースにできない、または競合サービスを作りたい。** BUSL-1.1 の商用条件を契約で決めます。保守者に連絡してください。この経路でも非商業利用は無料のままで、各リリースは公開から 4 年で AGPLv3 に切り替わります。制限には期限があり、恒久ではありません。

**あなたのデータはライセンスの対象外です。** Experientia で蓄積したもの、エクスポートしたものは、生のセッションから手法、好みまで、すべてあなたのもので、条件は付きません。商用利用もクローズドソースも第三者への譲渡も制限されません。ライセンスが縛るのはこの製品のコードだけです。
