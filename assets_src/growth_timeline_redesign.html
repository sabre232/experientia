改了什么（按收益排序）

  1. 按天分组 + 旧日折叠：默认只展开最近一天，更早的日子收成「日期 · N 个节点」一行，点开展开。50 个节点从「42 行墙」变成「4 行 + 2 个折叠条」。
  2. ×N 合并展示：同一天里连续出现的同型节点自动合成一条「×5」（纯展示层合并，changelog 数据、编辑/删除索引零改动），点开后逐条还原、逐条可编辑。
  3. 人话化：复盘 workbuddy 会话 00000000-000… → 其他/未分类 新增 1 条候选经验（文件通道） → 「从 workbuddy 的一次会话学到 1 条新经验」，会话 ID/通道降级到灰色副行。解析是 best-effort：用户改过的节点不匹配模板就原样显示，零风险。
  4. 类型标签 + 同色圆点：新经验（橙）/ 方法升级（绿）/ 偏好归纳（蓝）/ 成就（金）四类标签 + 时间轴圆点同色，一眼看出「今天学了什么」。[auto] 标保留（§11 既有约定，用户要能认出"哪些是我没点过的"）。
  5. 操作降噪：每行常驻的「编辑/删除」两个实线按钮 → 右侧一个 ⋯ 菜单（hover 出现）；「每个节点可编辑/删除」这句操作说明从标题挪到卡头右上角的灰色说明。
  6. 删除语义不变：删除=归档（deprecated/ 保留 30 天可恢复），菜单里把后果写明白「删除（归档 30 天可恢复）」。

固化成方法之后，信息量怎么控制不爆炸

L1 · 默认

家底

KPI 卡 + 方法沉淀概览。回答「我现在有什么」：几个方法、几类熟练、几个坑。用户每天只看这一层。

L2 · 按需

过程

学习历程。回答「怎么来的」：按天分组 + ×N 合并 + 旧日折叠。默认只露最近一天，往历史里走要主动点。

L3 · 审计

原料

完整 changelog + deprecated/ 归档 + 经验流原文。只有「展开全部」和归档入口能看到，平时不占任何版面。

1
记录粒度从「条」改成「事件」。一次复盘产出 3 条候选经验，现在落 3 个节点——42 条墙里绝大部分是这么来的。改成按事件落：一次复盘 1 个节点（「从 N 次会话学到 M 条新经验」），一次方法升级 1 个节点。节点数从 O(经验条数) 降到 O(学习事件数)。
数据层 · 需维护者拍板
2
固化后降级。候选经验一旦确认写进方法，它的单独节点就变成「原料」——默认折叠在对应「方法升级」里程碑节点下，点里程碑才下钻出原始节点。用户在 L2 看到的永远是里程碑，不是碎条。
数据层 · 需维护者拍板
3
展示层聚合（本次已做）。×N 合并、旧日折叠成一行、会话 ID 降级到副行、默认视图只展开最近一天。即使数据层粒度不改，墙也立不起来。
展示层 · 本次实现
4
衰减与出口（已有）。档 C 老化钟（30 天降权 / 90 天归档 / deprecated 30 天清理）管数据侧，UI 侧同节奏：默认视图只展示最近 14 天，更早的进 L3。
已有机制
注入侧（模型看到的）不受影响：800 token 总预算 + playbook 200 行压缩 + 近义合并（§17.3 / §18.2）已经是闭环，方法再多也不会把上下文撑爆。要控制的是「人看到的」，不是「模型看到的」——两层预算各管各的。
