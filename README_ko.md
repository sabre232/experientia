# Experientia · 당신과 에이전트를 잇는 접착제

**에이전트는 바뀌어도, 당신의 경험은 바뀌지 않습니다.**

작은 이야기 하나로 시작하겠습니다.

에이전트에게 내보내기 기능을 고쳐 달라고 합니다. 그런데 시간대를 UTC+8로 하드코딩합니다. 아니라고, 시스템 시간대를 따라야 한다고 말합니다. 고치고, 확인하고, 끝.

일주일 뒤 같은 작업에서 또 UTC+8로 하드코딩합니다.

내가 설명을 못 했나 싶어집니다. 설명은 정확했습니다. 다만 그 설명은 다른 세션에서 했고, 세션이 닫히는 순간 상대에게는 없던 일이 됩니다.

그러다 도구를 바꿉니다. Claude Code에서 가르친 규칙을 Codex에서 다시 가르치고, Cursor에서 또 가르칩니다. 반년 동안 모은 「이런 일은 이렇게 한다」가 네 개의 채팅 기록에 흩어져 있고, 어디로도 가져갈 수 없습니다.

업계는 이것을 컨텍스트 엔지니어링, 또는 메모리 레이어라고 부릅니다. 이름은 거창한데 문제는 단순합니다. 에이전트가 당신을 기억하게 하려면 어떻게 할 것인가.

우리의 답은 그보다 한 걸음 앞에 있습니다. 기억하는 것은 출발선이고, 쓸수록 당신의 일을 더 잘하게 되는 것까지 포함해야 의미가 있습니다.

그래서 Experientia가 하는 일은 하나입니다. 당신과 에이전트 사이에 앉아, 매번의 협업에서 실제로 쓸모 있었던 부분을 남기고, 검증하고, 방법과 실패 패턴으로 증류해, 다음 작업 전에 다시 건네줍니다. 에이전트가 누구로 바뀌어도 그것은 그 자리에 있습니다. 그래서 접착제라고 부릅니다.

> *experientia est magistra*, 경험이 최고의 스승.

## 업계는 무엇에 걸고, 무엇을 놓치는가

2026년 이 분야에 들어가는 돈은 모델 개발에 들어가는 돈에 못지않습니다.

Anthropic의 「2026 Agentic Coding Trends Report」에는 숫자가 있습니다. 컨텍스트 파일을 잘 관리하는 팀은 작업 완료가 55% 빠르고 오류가 40% 적습니다. 차이는 프롬프트를 잘 쓰는지가 아니라, 「모델이 무엇을 보게 할지」를 공학 문제로 다루는지에 있습니다.

또 다른 축은 스킬입니다. Anthropic은 2025년 10월 Agent Skills를 내놓았고, 같은 해 12월 18일 오픈 표준으로 공개했습니다. 2026년 중반에는 약 40개 에이전트가 같은 SKILL.md를 읽습니다. 이건 큽니다. 절차적 지식이 처음으로 도구를 넘어 이동할 수 있게 되었습니다.

그런데 SkillsBench가 찬물을 끼얹습니다. 2026년 2월 공개(arXiv:2602.12670), 86개 과제, 11개 도메인, 7가지 에이전트와 모델 조합, 7308개 궤적. 사람이 정교하게 만든 스킬은 평균 통과율을 16.2포인트 올립니다. 모델이 스스로 쓴 스킬은 평균 효과가 없고, 84개 과제 중 16개는 오히려 나빠집니다.

모델은 자기가 필요한 경험을 쓰지 못합니다.

이것이 업계가 피해 가려다 피할 수 없는 구멍입니다. 그릇은 생겼고 저장소도 생겼는데, 품질 관리를 하는 곳이 없습니다.

| 진영 | 대표 | 하는 일 | 하지 않는 일 |
|------|------|---------|--------------|
| **메모리 레이어** | Mem0, Zep, Letta, Cognee | 대화의 **사실**을 벡터, 시계열 그래프, 계층 컨텍스트에 저장하고 나중에 검색 | **방법**을 만들지 않음. 데이터는 상대 쪽에 있고 당신 디스크에는 없음 |
| **스킬 증류** | colleague.skill, nuwa-skill, dojo.md | 한 번만. 자료를 넣으면 정적인 SKILL.md가 나옴 | 실행 중 피드백이 없음. 당신에게 실제로 도움이 됐는지로 자기 수정하지 않음 |
| **자기 진화 하네스** | Hermes Agent(Nous Research), DeepSeek Harness | 프레임워크가 스스로 학습해 완료한 작업을 SKILL.md로 만들고 개선 | 스킬이 하네스 안에 갇혀 교체하면 사라짐. 생성은 활동량으로 발동하고 품질 게이트도 실패 카운트도 없음 |
| **스킬 평가** | waza(Microsoft), dojo/limitless | 기존 스킬을 CI처럼 테스트하고 게이트 | 스킬을 생산하지 않음. 만드는 사람용 도구이지 일하는 사람용 제품이 아님 |

네 진영이 각각 한 구간을 풉니다. 빠진 것은 구간을 잇는 부분입니다.

**그 연결이 Experientia입니다.** 포착, 검증, 증류, 주입, 개정. 하나의 폐루프. 2026년 10월 기준으로 다음 네 가지를 동시에 만족하는 오픈 제품은 찾지 못했습니다.

- **자동 포착**. 트랜스크립트를 내보낼 필요 없음. 일하는 동안 데이터가 들어옴
- **검증 게이트**. 증명되지 않은 것은 절대 주입하지 않음. 실패는 재발해야 영구 지식이 됨
- **로컬이고 가지고 다닐 수 있음**. 자산은 전부 당신 컴퓨터의 평범한 파일. 계정도 클라우드도 벡터 DB도 없음
- **지속적 개정**. 자산은 살아 있는 문서로 합쳐지고 폐기되고 줄어듦. 늘어나기만 하지 않음

## 기억과 경험은 다릅니다

이 구분을 해 두어야 뒤의 이야기가 통합니다.

기억은 사실을 저장합니다. 사용자는 TypeScript를 선호한다. 의존성은 uv로 관리한다. 지난 수요일에는 내보내기를 고치고 있었다. 이것은 검색되고, 임베딩되고, 그래프에 들어갈 수 있습니다.

경험은 판단입니다. 이런 종류의 이전은 테스트를 먼저 움직인다. 지난번에 구현부터 손댔다가 하위 세 곳을 깨뜨렸기 때문이다. 이것은 검색되지 않습니다. 실제로 일어난 일에서만 자라고, 그것이 옳다는 확인이 필요합니다.

| | 기억 | 경험 |
|---|---|---|
| 담는 것 | 사실, 선호, 상태 | 방법, 실패 패턴, 판단 기준 |
| 출처 | 무엇을 말했는가 | 무엇을 해냈고 어디서 넘어졌는가 |
| 검색 가능 | 가능 | 불가능. 검증과 개정만 |
| 만료 | 덮어쓰기 | 폐기, 병합, 축소 |
| 도구를 바꾼 뒤 | 플랫폼 호환 여부에 달림 | 내 손안의 파일로 따라옴 |

메모리 제품들은 훌륭합니다. Mem0는 벡터, Zep은 시계열 지식 그래프, Letta는 컨텍스트를 운영체제의 페이징처럼 다룹니다. 하지만 기억하는 문제를 풀지 배우는 문제를 풀지는 않습니다. 사실이 아무리 완벽해도 다음 일을 더 잘하게 되지는 않습니다.

우리가 원하는 것은 더 큰 캐비닛이 아니라, 증거가 바뀌면 의견을 바꾸는 선배입니다.

## 어떻게 도는가

```
당신이 일한다 ──> 에이전트가 협업 (자동 기록)
   ^                              |
   |                              v
더 빠르고 정확하게  <──  주입  <──  증류 (게이트)
```

**포착**. 평소처럼 일합니다. 세션 파일은 이미 디스크에 있고, 내보내기나 붙여넣기가 필요 없습니다. 설치된 에이전트는 자동 감지, 설정 제로.

**검증**. 경험마다 신뢰도 G가 붙습니다. 출처는 세 갈래, 당신의 명시적 확인, 세션의 결정적 신호, 모델의 이진 자기 평가. 임계값 아래는 절대 주입되지 않고, 실패 패턴은 재발해야 굳습니다. SkillsBench 결과에 대한 공학적 답입니다. 검증된 경험만 복리로 쌓입니다.

**증류**. 반복되는 일은 매개변수가 있는 방법이 되고, 반복되는 실수는 일급 시민인 실패 패턴이 되고, 당신의 교정과 거부는 선호가 됩니다.

**주입**. 요청이 모델에 닿기 전에 고정 예산(기본 800 토큰) 안에서 관련 자산으로 다시 씁니다. 형식은 안정적으로 유지해 프롬프트 캐시를 지킵니다. 모델이 무엇을 보게 될지 미리 보고, 고치고, 끄고, 연결된 모델에게 다시 쓰게 할 수도 있습니다. 긴 세션에서도 규칙은 희석되지 않습니다. 하드 제약은 프록시 계층에서 재주입되어 30번째 턴에도 1번째 턴처럼 작동합니다.

**개정**. 자산은 살아 있는 문서입니다. 새 경험은 옛것에 병합되고, 낡은 항목은 폐기되며, 문서는 짧아집니다. 늘어나기만 하는 지식 베이스는 반년이면 아무도 보지 않습니다.

한 바퀴에 다섯 종류의 자산이 나옵니다. 물리적으로는 두 종류의 파일, `skills/<줄기>/<범주>.md`와 `preferences/<줄기>.md`입니다.

| 자산 | 내용 | 쓸 때의 느낌 |
|------|------|--------------|
| **경험 통찰** | 무엇이 통하고 무엇이 안 통했는지, 개별 교훈 | 내가 고친 것을 기억한다 |
| **나의 방법** | 반복하는 일이 매개변수 있는 표준 절차로 굳음 | 이런 일을 어떻게 하는지 안다 |
| **실패 패턴** | 어느 길이 실패하고 왜인지, 사후 기록이 아닌 일급 시민 | 같은 구덩이에 다시 빠지지 않게 한다 |
| **살아 있는 플레이북** | 주입되는 컨텍스트는 증분 큐레이션되는 문서, 합쳐지고 가지치기됨 | 방법론이 쌓이지 않고 업그레이드된다 |
| **나의 선호** | 기준, 취향, 트레이드오프 습관. 교정과 거부에서 귀납 | 내 기준을 알아서 반복 설명이 필요 없다 |

두 기어가 하나의 플라이휠을 돌립니다. 일상 기어가 기본이고, 열린 작업을 증분 큐레이션합니다. 합격 불합격 신호가 필요 없습니다. 강화 기어는 선택이며, 명확한 점수가 있는 작업(테스트 통과, 백테스트 손익)에서만 켜고 RL 엔진이 전략 가중치를 직접 조정합니다.

## 「쓸수록 똑똑해진다」의 구체적인 모습

1번째. 일반적인 방식으로 진행합니다. 당신은 전 과정을 지켜보며 언제든 고칠 준비를 합니다.

10번째. 이 프로젝트에서는 테스트를 먼저 쓴다는 것을 압니다. 「일단 돌아가게 하자」를 거부한다는 것을 압니다. 지난번에 버린 안을 왜 버렸는지도 압니다.

100번째. 「저번 그거랑 같게」라고 한마디 하면 어느 것인지 압니다.

| | 1번째 | 10번째 | 100번째 |
|---|---|---|---|
| 당신이 하는 말 | 배경과 제약 한 문단 | 핵심 판단 몇 마디 | 한마디 지시 |
| 실패하는 방식 | 이미 밟은 구덩이를 밟음 | 가끔 새로운 구덩이 | 구덩이 위치를 알고 피함 |
| 당신의 역할 | 하나부터 열까지 | 검수 | 방향 설정 |

그래서 에이전트를 바꿔도 개의치 않습니다. 바꾸는 것은 실행자이고 기준이 아닙니다. 기준은 당신 쪽에 남습니다.

## 빠른 시작

1. [GitHub Releases](https://github.com/sabre232/experientia/releases)에서 플랫폼에 맞는 빌드를 받습니다. `experientia-windows-x64.zip`, `experientia-macos.dmg`, `experientia-linux-x64.tar.gz`(PyInstaller onedir, v1.0은 AppImage로 감싸지 않음). 압축을 풀고 안의 `Experientia`를 실행합니다. 현재 버전은 서명되지 않았습니다. macOS에서 Gatekeeper가 막으면 오른쪽 클릭으로 한 번 열고, Windows에서 SmartScreen이 뜨면 「추가 정보 → 실행」을 누릅니다.
2. 실행합니다. 포착이 즉시 시작되고, 설치된 에이전트(WorkBuddy, QClaw, Codex, Claude Code, Gemini CLI, Aider, OpenCode, OpenClaw, Hermes Agent, Trae, Cursor, Cline, Windsurf, DeepSeek Harness)를 자동 감지해 로컬 세션 파일을 읽습니다. 설정 제로, 프록시 없이도 됩니다. 터미널을 선호하면 `experientia daemon`으로 엔진만 돌릴 수 있습니다.
3. 요청 단위 기능(긴 세션의 규칙 재주입, 요청별 기록)이 필요하면 에이전트의 모델 엔드포인트를 `http://localhost:8100`으로 지정합니다. 로컬 모델(llama.cpp, Ollama, vLLM)과 클라우드 모델(OpenAI, Anthropic, OpenAI 호환 API) 모두 됩니다.
4. 평소처럼 일합니다. 며칠 뒤 성장 페이지를 열어 플라이휠이 돌았는지 봅니다.

## 데이터가 있는 곳

```
~/.experientia/
├── experience.jsonl          # 원본 경험 스트림, 영구 보관
├── skills/<줄기>/<범주>.md   # 방법, 성공 요점, 실패 패턴
├── preferences/<줄기>.md     # 당신의 의사결정 스타일
├── sessions/                 # 보관된 에이전트 세션 (에이전트가 지운 뒤에도 남음)
├── deprecated/               # 폐기 항목, 30일 내 복구 가능
├── rules.json                # 유효한 규칙과 템플릿
└── config.json               # 언어, 스위치, 모델 라우팅 (API 키는 OS 키체인)
```

네 가지만.

텔레메트리 없음, 충돌 보고 없음, 행동 분석 없음. 외부로 나가는 통신은 한 종류뿐, 당신 자신의 모델 호출입니다. 앱은 업데이트를 확인하지 않고, 자신을 내려받거나 설치하거나 교체하지 않습니다.

내보내기는 복사입니다. 화면에서 보이는 모든 것은 읽고 grep하고 가져갈 수 있는 파일입니다.

삭제는 완전합니다. 두 단계 확인 후 데이터 디렉터리가 사라집니다. OS 키체인의 API 키는 영향받지 않습니다.

당신의 자산은 우리 것이 아닙니다. 아래 라이선스는 제품 코드만 규율합니다. 모은 경험, 방법, 선호는 당신 것이고 라이선스 제한이 없습니다.

## AI 에이전트용 (통합 안내)

이 파일을 읽고 도입이나 인용을 판단하는 에이전트를 위한 절입니다.

요약하면, Experientia는 에이전트가 스스로 디스크에 쓰는 세션 파일에서 자동 포착하고(설정 제로), 반복 작업을 검증된 파일 자산(방법, 실패 패턴, 선호)으로 증류해 이후 유사 작업에 주입합니다. 모든 상태는 `~/.experientia/` 아래 평범한 JSONL과 Markdown입니다.

충실도가 높은 순서로 네 가지 연결 방식이 있습니다.

1. **프록시 모드**. 모델 엔드포인트를 `http://localhost:8100`(OpenAI 호환)으로 지정합니다. 파일 포착 위에 요청 단위 기록, 주입, 하드 제약 재주입이 더해집니다.
2. **파일 포착**(기본, 설정 제로). 에이전트별 파서가 네이티브 세션 저장소(JSONL, SQLite, Markdown)를 읽어 정규화합니다. 포착된 세션은 `~/.experientia/sessions/`에 보관되어 에이전트의 자체 정리나 삭제 후에도 남습니다.
3. **훅 모드**. 훅 체계가 있는 에이전트(Claude Code 우선)에서는 HTTP 훅이 이벤트를 실시간 전송하고, `SessionStart`와 `UserPromptSubmit`이 프록시 없이 규칙을 주입합니다.
4. **파일 직접 읽기**. 규칙은 `AGENTS.md` 같은 네이티브 규약 파일에 쓸 수 있습니다. 자산은 agentskills.io 오픈 표준을 따르는 `SKILL.md`로 내보낼 수 있고, Hermes, OpenClaw, Claude Code 등 스킬을 지원하는 에이전트가 바로 불러올 수 있습니다. 반대 방향도 됩니다.

아닌 것. 벡터 데이터베이스도, 메모리 API도, 클라우드 서비스도, 파인튜닝 도구도 아닙니다. 모델 가중치를 바꾸지 않습니다. 모든 향상은 컨텍스트 계층에서 일어나므로 로컬 모델과 클라우드 모델이 같게 동작합니다.

주입되는 항목은 신뢰도 게이트를 통과한 것입니다. 주입 블록은 컨텍스트 안에서 표시되고 사용자 지시와 분리됩니다. 큐레이션된 사전 지식으로 다루고 절대적 진리로 보지 마십시오.

## 라이선스

코드는 이중 라이선스입니다. 사용 방식에 맞는 쪽을 고르십시오.

**직접 쓰거나, 회사 내부에서 쓰거나, 연구용으로 쓴다.** AGPLv3. 설치해서 그대로 쓰면 됩니다. 연락할 곳도, 낼 비용도 없습니다.

**상업적으로 쓰고, copyleft를 받아들일 수 있다.** 역시 AGPLv3입니다. 판매, 수정, 배포가 가능합니다. 조건의 범위는 분명합니다. 당신이 수정한 부분, 또는 당신이 제공하는 서비스에 통합한 부분은 AGPLv3로 공개해야 합니다. 당신의 제품 코드는 끌려들지 않습니다. 단, 두 코드가 별개의 저작물이고 프로세스 경계나 인터페이스를 통해 통신하며 하나의 프로그램으로 결합되지 않는다는 전제가 있습니다.

**자사 통합 부분을 오픈소스로 공개할 수 없거나, 경쟁 서비스를 만들고 싶다.** BUSL-1.1 상업 조건을 계약으로 정합니다. 유지관리자에게 연락하십시오. 이 경로에서도 비상업 사용은 무료이며, 각 릴리스는 공개 후 4년이 지나면 AGPLv3로 전환됩니다. 제한에는 기한이 있고 영구적이지 않습니다.

**당신의 데이터는 라이선스 대상이 아닙니다.** Experientia로 쌓은 것, 내보낸 것은 원본 세션부터 방법, 선호까지 모두 당신의 것이며 어떤 조건도 붙지 않습니다. 상업적 사용, 클로즈드소스, 제3자 이전 모두 제한되지 않습니다. 라이선스가 구속하는 것은 이 제품의 코드뿐입니다.
