# Experientia · 你和 agent 之間的那層黏合劑

**agent 會換，你的經驗不換。**

先說件事。

你讓 agent 改一個匯出功能，它把時區寫死成 UTC+8。你說不對，要跟著系統時區走。它改了，你驗收，收工。

過了一週，同樣的事，它又寫死 UTC+8。

你開始懷疑是不是自己沒講清楚。其實你講得很清楚，只是那一遍講在另一個工作階段裡。工作階段一關，對它來說就等於沒發生過。

再往後你換了工具。在 Claude Code 裡教會它的規矩，到 Codex 得再講一遍，到 Cursor 再講一遍。半年攢下來的「這類活該怎麼做」，散在各家的對話紀錄裡，誰也帶不走。

業界把這件事叫上下文工程，也叫記憶層。名字聽起來玄，問題很樸素，怎麼讓 agent 記住你。

我們的判斷再往前一步。記住你只是起點，讓它越用越會做你的活，才算數。

所以 Experientia 做的事很簡單。它坐在你和 agent 中間，把每次協作裡真正有用的部分留下來，驗證，蒸餾成方法和失敗模式，下一次開工前遞回去。agent 換成誰它都在，這就是我們說它是黏合劑的意思。

> *experientia est magistra*，經驗是最好的老師。

## 業界在賭什麼，漏了什麼

2026 年這大半年，這塊的投入一點不比做模型少。

Anthropic 在《2026 Agentic Coding Trends Report》裡給了一組數字，上下文檔案維護得好的團隊，任務完成快 55%，錯誤少 40%。差距不在提示詞寫得漂不漂亮，在於有沒有把「模型該看到什麼」當成工程問題來做。

另一條線是技能。2025 年 10 月 Anthropic 推出 Agent Skills，同年 12 月 18 日開放成標準，掛在 agentskills.io，到 2026 年中大約四十個 agent 認這個 SKILL.md 格式。載體統一這件事很重要，經驗第一次可以跨工具搬運了。

然後 SkillsBench 潑了盆冷水。這個基準 2026 年 2 月發布（arXiv:2602.12670），86 個任務、11 個領域、7 種 agent 與模型組合、7308 條軌跡。結論很刺眼，人精編的技能平均把通過率抬 16.2 個百分點，模型自己給自己寫的技能平均沒有收益，84 個任務裡有 16 個是負的。

一個模型，寫不出它自己真正需要的那份經驗。

這正好是業界最想繞、又繞不過去的地方。載體有了，儲存有了，沒人管品質把關。

| 陣營 | 代表 | 做了什麼 | 沒做什麼 |
|------|------|----------|----------|
| **記憶層** | Mem0、Zep、Letta、Cognee | 把對話裡的**事實**存進向量庫、時序圖或分層上下文，之後檢索回來 | 不產出**方法**。資料在它們那邊，不在你硬碟上。 |
| **Skill 蒸餾** | colleague.skill、nuwa-skill、dojo.md | 一次性，餵素材進去，產出一份靜態 SKILL.md | 沒有執行時回饋。這份 skill 永遠不會因為「對你到底有沒有用」而自我修訂。 |
| **自進化 harness** | Hermes Agent（Nous Research）、DeepSeek Harness | agent 框架自己學習，把做完的任務沉澱成 SKILL.md 並持續改 | 技能鎖在 harness 裡，換 agent 就報廢。生成靠活躍度觸發，沒有品質門檻，失敗不計數就固化成永久知識。 |
| **Skill 評測** | waza（微軟）、dojo/limitless | 像 CI 測程式碼一樣測既有的 skill | 不生產 skill。是給 skill 作者的工具，不是給幹活的人的產品。 |

四家都解決了一段。缺的是把它們接起來的那一段。

**Experientia 要補的就是這一段**，捕獲、驗證、蒸餾、注入、修訂，一條閉環。截至 2026 年 10 月，我們沒找到同時滿足下面四點的開源產品。

- **自動捕獲**，不靠你手動餵 transcript，幹活的同時資料自己進飛輪
- **驗證門檻**，沒被證實的東西永不注入，失敗要重複出現才會成為永久知識
- **本地且可帶走**，所有資產都是你機器上的純檔案，無帳號、無雲端、無向量庫
- **持續修訂**，資產是活文件，會合併、會棄用、會收縮，不是只增不減

## 記憶和經驗不是一回事

這個區分要說清楚，後面的話才講得下去。

記憶存事實。使用者偏好 TypeScript，專案用 uv 管依賴，上週三在改匯出。這些可以檢索、可以向量化、可以塞進圖資料庫。

經驗是判斷。這類遷移先動測試再動實作，因為上次直接改實作炸了三個下游。這條檢索不出來，它只能從真實發生過的事裡長出來，還得有人確認它是對的。

| | 記憶 | 經驗 |
|---|---|---|
| 內容 | 事實、偏好、狀態 | 方法、失敗模式、判斷標準 |
| 來源 | 說了什麼 | 做成了什麼、在哪摔過 |
| 能不能檢索 | 能 | 不能，只能驗證和修訂 |
| 過期 | 覆蓋即可 | 要棄用、要合併、要收縮 |
| 換工具之後 | 取決於平台是否支援互通 | 檔案在你手裡，跟著你走 |

做記憶的那批產品都很強，Mem0 走向量，Zep 走時序知識圖譜，Letta 把上下文當記憶體分頁。但它們解決的是記住，不是學會。事實記得再全，也不等於下次這個活能做得更好。

我們要的不是一個更全的檔案櫃，是一個會改口的資深同事。

## 它怎麼轉

```
你幹活 ──> agent 協作（自動記錄）
   ^                        |
   |                        v
更快更好  <──  注入  <──  蒸餾（帶門檻）
```

**捕獲**。你照常幹活，工作階段檔案本來就在硬碟上留著，不用你匯出、不用你貼。裝了哪些 agent 自動偵測，零設定。

**驗證**。每條經驗帶一個信賴度 G，來源分三級，你的明確確認、工作階段裡的確定性訊號、模型給出的二值自評。低於門檻的永不注入，失敗模式要重複出現才會固化。這是對 SkillsBench 那個結論的工程回答，只有被驗證的經驗才配複利。

**蒸餾**。重複出現的活變成帶參數的方法，踩過的坑變成一等公民的失敗模式，你的糾正和拒絕歸納成偏好。

**注入**。每個請求到達模型之前，在固定預算內（預設 800 token）用相關資產重寫，格式穩定以保住 prompt cache。你能預覽模型將看到什麼，能改、能停用，也能讓接入的模型幫你改寫。長工作階段也不會稀釋規則，硬約束在代理層重注入，第 30 輪和第 1 輪一樣管用。

**修訂**。資產是活文件，新經驗併進舊的，過時的條目棄用，文件會變短。只增不減的知識庫，半年之後就沒人看了。

一輪下來產出五類資產，物理上其實是兩種檔案，`skills/<主幹>/<類別>.md` 和 `preferences/<主幹>.md`。

| 資產 | 是什麼 | 用起來的感受 |
|------|--------|--------------|
| **經驗洞察** | 一條條具體的教訓，什麼行、什麼不行 | 它記得我糾正過它什麼 |
| **我的方法** | 反覆做的活結晶成帶參數的標準流程 | 它知道這類活怎麼做 |
| **失敗模式** | 哪條路會失敗、為什麼，一等公民而非事後補記 | 它不讓我重蹈覆轍 |
| **活的 playbook** | 注入的上下文是被增量策展過的檔案，新的併進舊的，過時的棄用 | 它的方法論在升級，不是在堆積 |
| **我的偏好** | 你的標準、品味、取捨習慣，從糾正和拒絕裡歸納 | 它懂我的標準，我不用反覆解釋 |

兩種檔位共用一個飛輪。日常檔是預設，開放式工作做增量策展，不需要好壞訊號。強化檔要你手動開，任務有明確評分時（測試過沒過、回測盈虧）才開，RL 引擎直接調策略權重。

## 越用越懂你，具體長什麼樣

第 1 次，它按通用套路來，你得盯著，隨時準備糾偏。

第 10 次，它知道這個專案裡測試先寫，知道你會拒絕「先跑通再說」的方案，也知道你上次砍掉的那個方案為什麼被砍。

第 100 次，你只說一句「照上次那個來」，它真的知道是哪個。

| | 第 1 次 | 第 10 次 | 第 100 次 |
|---|---|---|---|
| 你要說的話 | 一大段背景加約束 | 幾句關鍵判斷 | 一句指路 |
| 它踩坑的方式 | 踩你早就踩過的 | 偶爾踩新的 | 知道坑在哪，繞著走 |
| 你的角色 | 手把手 | 驗收 | 定方向 |

這也是為什麼它不介意你換 agent。你換的是執行者，不是標準。標準在你這邊，換個執行者照樣執行。

## 快速開始

1. 到 [GitHub Releases](https://github.com/sabre232/experientia/releases) 下載對應平台的套件，`experientia-windows-x64.zip`、`experientia-macos.dmg`、`experientia-linux-x64.tar.gz`（PyInstaller onedir 目錄包，v1.0 不套 AppImage 殼）。解壓後執行包內的 `Experientia`。目前版本未簽章，macOS 被 Gatekeeper 攔住就右鍵打開一次，Windows 跳出 SmartScreen 就點「更多資訊 → 仍要執行」。
2. 啟動應用程式。檔案捕獲立刻開始，它會自動偵測已安裝的 agent（WorkBuddy、QClaw、Codex、Claude Code、Gemini CLI、Aider、OpenCode、OpenClaw、Hermes Agent、Trae、Cursor、Cline、Windsurf、DeepSeek Harness），讀它們的本地工作階段檔案。零設定，不用代理也能跑。偏好終端機的可以用 `experientia daemon` 只跑引擎不開介面。
3. 想拿到請求級的能力（長工作階段的規則重注入、逐請求記錄），把 agent 的模型端點指到 `http://localhost:8100`。本地模型（llama.cpp、Ollama、vLLM）和雲端模型（OpenAI、Anthropic、任何 OpenAI 相容 API）都行。
4. 照常幹活。過幾天打開成長頁，看飛輪轉沒轉。

## 你的資料在哪

```
~/.experientia/
├── experience.jsonl          # 原始經驗流，永久保留的原料
├── skills/<主幹>/<類別>.md   # 方法、成功要點、失敗模式
├── preferences/<主幹>.md     # 你的決策風格
├── sessions/                 # 歸檔的 agent 工作階段（agent 自己清掉之後還在）
├── deprecated/               # 棄用條目，30 天內可恢復
├── rules.json                # 生效中的規則與範本
└── config.json               # 語言、開關、模型路由（API Key 在系統金鑰庫）
```

四句話。

無遙測，無當機回報，無行為分析，出站流量只有一類，你自己的模型呼叫。應用程式不檢查更新，不下載、不安裝、不替換自己。

匯出就是複製一個資料夾。你在介面上能看到的東西，都能讀、能 grep、能帶走。

刪除是徹底的。兩步確認之後整個資料目錄移除，系統金鑰庫裡的 API Key 不受影響。

你的資產不歸我們。下面那份授權只約束產品程式碼，你攢下來的經驗、方法、偏好歸你，沒有授權限制，任何語言、任何用途。

## 給 agent 的整合說明

你要是正在讀這份檔案、判斷要不要接入的 agent，看這一段。

一句話，Experientia 從 agent 自己落盤的工作階段檔案裡自動捕獲（零設定），把重複性工作蒸餾成經驗證的檔案資產（方法、失敗模式、偏好），再注入到後續相似任務裡。全部狀態都是 `~/.experientia/` 下的純 JSONL 和 Markdown。

按保真度從高到低，四種接法。

1. **代理模式**。把模型端點指到 `http://localhost:8100`（OpenAI 相容）。在檔案捕獲之上疊加請求級記錄、注入、硬約束規則重注入。
2. **檔案捕獲**（預設，零設定）。per-agent 解析器讀原生工作階段儲存（JSONL、SQLite、Markdown）並正規化，捕獲的工作階段歸檔到 `~/.experientia/sessions/`，在 agent 自清理或解除安裝之後依然留存。
3. **hook 模式**。對有 hook 體系的 agent（Claude Code 首發），http hook 即時推事件，`SessionStart` 和 `UserPromptSubmit` 在不掛代理的情況下注入規則。
4. **直接讀檔案**。規則可以寫進 agent 原生慣例檔案（如 `AGENTS.md`），資產可以匯出成遵循 agentskills.io 開放標準的 `SKILL.md`，Hermes、OpenClaw、Claude Code 這些支援 skill 的 agent 能直接載入。反過來也行，它們的 SKILL.md 能讀進來做參考。

它不是什麼，不是向量資料庫，不是記憶 API，不是雲端服務，不是微調工具。它不改模型權重，所有提升都發生在上下文層，所以本地模型和雲端模型表現一致。

注入的條目都過了信賴度門檻，注入區塊在上下文裡帶標記，跟你的指令隔開。當經過策展的先驗知識用，別當聖旨。

## 授權

雙授權，用的時候選一個。

**AGPLv3**，免費自助，個人、非商業、以及接受 copyleft 的公司都能用。可以商用，但改了之後或者整合進你對外提供的服務，衍生作品得按 AGPLv3 開源。

**BUSL-1.1**，商業授權，協議制。需要乾淨閉源整合，或者想基於它做競爭服務的公司，聯絡維護者。參數是 Change Date 發布後 4 年，Change License 轉 AGPLv3，非商業用途免費。

這是 CockroachDB 那套打法，程式碼從第一天就全公開、可稽核、可 fork，同時留一條讓生態保持誠實的商業路徑。

**你的資料豁免授權。** 你透過 Experientia 攢下來或匯出的一切，歸你所有，不帶任何授權條款。
